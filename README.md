# makefun-frontend

A fast, dependency-free make.fun frontend: plain static files in `app/` (vanilla ES modules and a stylesheet, no build step) that read make.fun's public API.

- **Board + bounty, master–detail** (`#/`, `#/bounty/<slug>`): on a wide screen (≥ 1000px) a dense table of the bounties sits on the left (category, live pot and entry fee, a ticking countdown with a bar of the entry window used, entries and **your odds**, plus an "Opening soon" group) under a **Live N · Ended M** toggle (Ended: past the deadline, judging, results soon, and any resolved bounty the list carries; `E`, or `?show=ended`), and below it the **latest entries** across make.fun. The selected bounty's page sits on the right: title with category and status, live pot, time left, entry fee, entries, **your odds** beside "Enter on make.fun", the rewards table (1st, 2nd and 3rd on their own rows, then consecutive places that pay the same grouped, "4th–10th · $29.94 each", fee share and a live-pot total; `placeRuns`, which also groups the leaderboard's place chips) beside a **dates timeline** (Opened → the entry phase → Deadline → final judging → Results by, with a **Now** marker; `timeline`), then a **Leaderboard · Top 10** (rank, avatar, @handle, entry, judge win rate with its 90% interval, prize now, "of N ranked", "Full leaderboard →"; `renderTop10`), then the description and rules. Picking another bounty repaints the detail pane only (`selectBounty`). Category, sort and Live/Ended live in the URL.
- **Your odds** (`oddsFor`): the live pot divided by the entries and the entries per paid place ("1 in 30 paid"); "Best odds" sorts by it.
- **Leaderboard** (`#/bounty/<slug>/leaderboard`): pot, clock, fee, entries and paid places on top, then a **virtual list** of every row (`virtualRows`: a 7,000-row board keeps about 17 rows in the DOM, reused while scrolling) with handle search and each place's prize now.
- **Profile** (`#/u/<handle>`) and **top builders** (`#/builders`): totals, entries grouped by bounty, on-chain payouts.
- **Live activity** (`renderTicker`): a one-line ticker in the header, "100+ entries in the last hour · @handle entered <bounty>", turning over every 5 s, from `GET /api/activity/entries`; the board's latest entries share the same answer.
- **Keyboard** (`bindKeyboard`): ↑/↓ or j/k browse, Enter opens, `E` switches Live/Ended, `/` searches, `l` opens the leaderboard, Esc goes back. **Theme** (`applyTheme`): follows the system, toggle kept in `localStorage`. **Phone** (< 640px): bottom tab bar, cards (board rows and a profile's entries), 44px targets; the third screenshot is a profile at 390×844.

**Speed.** The first load is one file: `index.html`, **769 bytes gzip-9** (1,335 raw), a shell: the pre-paint theme script, the critical CSS for the header's box and a skeleton, and one module script, `import('./views/core.js')`. Everything else loads by literal `import()`: `views/core.js` (`route`, which names the view the hash asks for and its literal `import()`; `cachedFetch`; `revalidate`; `meter`), which starts the view's module, the stylesheet (`views/style.js`, a constructed `CSSStyleSheet`) and `views/shared.js` (`show`, `drawMeter`, the header's controls and ticker, the helpers) in parallel; the views are `views/board.js`, `views/leaderboard.js` and `views/profile.js` (profile and builders). The header's controls go in once the stylesheet is in, and a view only once its module and the stylesheet are in, so nothing paints unstyled; the shell's header box and skeleton have the finished page's geometry, so nothing moves between the first paint and the finished view (checked with the modules held back 1.5 s at 1280×800, 700×900 and 390×844, light and dark). Muted and status colours meet WCAG AA (≥ 4.5:1) on every background they sit on, in both themes.

**Few requests a view.** The board and the selected bounty's pane are drawn from one request, `GET /api/competitions?status=open&activity=times` (every open bounty's pot, fees, rewards, description and scoring; Live and Ended both come from it); that list is the bounty view's only first-paint request. Once the view is ready, in the background: the pane's Top 10 (a skeleton until it fills), `…/leaderboard?rows=first`, whose first rows come in full and every other row in brief, so it is also the whole leaderboard; the latest entries, `/api/activity/entries` (4.8 KB, the header ticker and the board's panel); and the bounty's own record, for its phases (final judging, results date) and rules, once the dates or the rules are in view (`lazyRecord`). The cover, `#/bounty/makefun-frontend-01`, reads "1 API request · 201 KB JSON · ready in ~400 ms · +3 background". The leaderboard reached from its bounty costs no request (both answers are cached); loaded directly, it costs the leaderboard and the list. A bounty that is not open any more costs its own record.

**Performance.** `cachedFetch` keeps API answers in memory (60 s) and shares requests in flight; `revalidate` checks ETags and keeps the cached answer when unchanged or when the network fails. Live refresh (60 s) patches rows in place (`patchRows` replaces only rows whose markup changed; `setHTML` touches a section only when its markup changed; countdowns tick in text nodes, `tickCountdowns`).

**The meter.** A slim bar on every screen shows what the view on screen cost, measured live: first-paint API requests, answers from the memory cache, ETag-unchanged answers, bytes (PerformanceResourceTiming where the server allows it, else the JSON size), rows patched and time to ready, then anything fetched after the view was ready (the Top 10, the activity, the record, live refresh) as "+N background (KB)".

## Run it

```sh
node serve.ts
```
